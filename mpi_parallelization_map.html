Pitfalls

      
Where the rewrite gets tricky

    

    

      

        
Merging
MPI-SYNC

        
N changes, the blocks have to be redistributed, and chains of close stars cross rank boundaries. Use --merge-radius 0 for the scaling runs. Otherwise treat merging as a rare event: gather everything, merge identically on every rank, redistribute.

      

      

        
Shared stop
MPI-SYNC

        
Today every process checks the time limit and Ctrl+C/SIGTERM on its own. If one rank stops a step early, the others wait forever in the next Allgatherv. Fix: one comm.allreduce(stop, op=MPI.LOR) per step.

      

      

        
Uneven blocks
MPI-KOMM

        
If N is not divisible by P, you need Allgatherv and Gatherv with counts and displs. The ring needs equal-sized buffers: pad every block to the largest one and give the padding stars mass 0.

      

      

        
Output
MPI-RANK0

        
print, results.csv, --save-final and plots on rank 0 only, after the data has arrived there via Gatherv or reduce. Cluster nodes have no display: matplotlib.use("Agg").

      

      

        
Kernel first
MPI-PARALLEL

        
The Python loop manages about 2·10⁷ pairs per second. Each rank then computes for so long that communication hardly registers and the scaling looks better than it is. Numba first, then measure.
