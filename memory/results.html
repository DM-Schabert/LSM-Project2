Memory: what fills a rank, and which limit comes first

The real start-up of the program, up to and including the force kernel, with the memory of every rank read after each phase. From 1 000 stars up to the whole catalogue (589 993), for Allgather, ring and 2D, for different tile sizes and from 1 to 48 ranks. At the end the largest N that memory allows stands next to the largest N that time allows.

Hypothesis. Memory of a rank ≈ M0 (Python, NumPy, pandas, MPI; more with a second node) + N · b (every rank gets the whole catalogue by Bcast, about 77 bytes per star, whatever the scheme) + the kernel's temporaries (56 bytes per pair of the current tile) + on rank 0 alone, pandas while reading the CSV. Then memory allows millions of stars per rank, while time allows far fewer: time is the limit, not memory. Memory would become the limit only for a kernel without tiles.

Which limit comes first

Memory: the N at which a rank would reach its share, from the measured model (M0 + N · b, rank 0 with its extra). Time: the N at which the steps no longer fit, with the time per star pair of v1 with the node full (from the C2/C3 runs). Naive kernel: one tile for the whole own block, as a fully vectorised kernel without tiles would do.

Every launch
How it is measured
  • memory/memory_probe.py calls the program's own functions, unchanged: parse_args, load_and_distribute, the ring's buffers, the 2D grid, block_accelerations; and does what main() does in between (rank 0 copies the start positions, the ring and 2D drop the full positions). So the memory is that of a real run, without computing whole time steps at 589 993 stars.
  • Memory: VmHWM (peak so far) and VmRSS (now) from /proc/self/status of every rank after every phase. The program itself only reports the peak of the largest rank (peak_memory_mb).
  • One job on two full nodes, --map-by core --bind-to core: P ≤ 24 on the first node. The subsets up to the whole catalogue are made in the job with isoeff/make_subset.py (the same files as GaiaSubsetSelection.py).
  • Cross-check: LSF's "Max Memory" of the whole job, from the end of the job log, against the sum over the ranks of one launch.
