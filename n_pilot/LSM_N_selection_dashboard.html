What this experiment shows

01 / Smaller N exposes MPI overhead. At two-node, P=32, communication was 31.89% for N=50 versus 21.85% for N=100.

02 / Adding ranks still helps, but with diminishing returns. For N=50 across two nodes, increasing 16 → 32 ranks improves throughput by about 21.6%, not 100%.

03 / Node placement matters. At equal rank counts (8 or 16), two-node throughput is consistently lower in the supplied results.

04 / N=50 is a useful stress case, with N=100 as a less extreme validation case. This motivates exploring communication optimisations.

Interpret with care: "MPI share" includes time spent inside the measured communication phase, potentially including waiting for other ranks; it is not necessarily pure network transfer. Confirm host placement using LSF logs. Phase times are slowest-rank diagnostics and need not sum to total.
